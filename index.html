Graph engineering, verified.

Most graph engineering material states rules. This one enforces them.

A contract-gated verification layer for multi-agent research pipelines. It reads a directory of versioned artifacts, validates each against a JSON Schema, walks the provenance hash chain, checks that the reviewer was not the producer, and returns an exit code. It orchestrates nothing and calls no model API.

Try it in 30 seconds

git clone https://github.com/huguryildiz/research-graph
cd research-graph
pip install -e .
rgraph demo
SCENARIO 1 · PASS

A clean run

Nine gates, no missing artifact, no broken hash chain. Exit 0.

SCENARIO 2 · FAIL

A fabricated citation

A source with no resolvable DOI. Gate E1 names it, says how to fix it, exits 1.

SCENARIO 3 · STALE

Data changed after the freeze

One byte edited post-freeze. The stale chain invalidates T2, V1 and M1.

Scenarios 2 and 3 are the point. Neither can be prevented by a prompt; both are caught by a file digest.

What it does not do

research-graph does not judge scientific correctness. It establishes that every artifact behind a claim is registered, versioned and traceable to its inputs. Every gate screen repeats this, passed or failed:
[----] Scientific correctness was not determined

Three files, three concerns

graph.yaml       ->  architecture   (which nodes, which edges, which gates)
assignment.yaml  ->  your wallet    (who runs which role)
providers.yaml   ->  the registry   (which providers exist, what they can do)

The same graph runs on anyone's combination of subscriptions. Adding a provider is a few lines of YAML; no code changes, because rgraph knows no provider — it only carries identity strings.

Which roles can you actually run?

Pick a provider per role. Options your subscription cannot support are struck through with the reason. This answers the question you have before installing anything — I only have ChatGPT; what do I get?
