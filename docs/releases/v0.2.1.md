# v0.2.1 — public beta for technical users

`v0.2.1` is a public-beta hardening release. It improves the first-run path,
preflights configured provider CLIs, and expands release-install verification.
It does not add an agent scheduler, a continuous execution loop, or model API
orchestration.

## What changed

- `rgraph doctor` checks the effective assignment, executable discovery on
  `PATH`, non-interactive login state, role capabilities, and assignments that
  would make T2 or M1 impossible to pass. Without a real provider call, model
  names are labelled `UNVERIFIED`; `--probe-models` makes one small call per
  distinct provider/model pair and exits `2` on rejection or timeout.
- Human gate and final release decisions are terminal-only and recorded under a
  self-declared name, including when `review --outcome` is supplied. Pipes,
  missing names, stale attestations, and changed artifacts remain protected by
  regression tests. A TTY is a workflow control, not identity authentication or
  proof that software is absent from the terminal.
- Challenge gates use a separate `rgraph challenge <GATE>` step. It starts one
  assigned reviewer CLI, records the exact provider/model argv, and binds the
  current inputs to digests of the captured prompt and response log. `rgraph
  check` is read-only and cannot manufacture a reviewer identity. Malformed
  output, a nonzero provider exit, or a reviewer modification to the run writes
  no gate record.
- Unit calls write host execution receipts that bind the assignment, argv,
  unique provider-log digest, input hashes and output hashes. Rejected calls do
  not advance the workflow merely because they left files behind. Hash-bound
  dataset sidecars are restricted to `run/data/`, and providers receive the
  active installation's artifact-only seal command rather than calculating
  hashes themselves.
- CI covers Python 3.11–3.13 on Linux, macOS, and Windows, installs a built wheel
  outside the checkout, checks local `uv tool` and `uvx` paths, and exercises an
  empty Git repository through the first agent dry-run.
- A tag workflow verifies the documented GitHub-pinned `uv tool install` and
  `uvx` commands before a GitHub release is published.
- A manual PyPI Trusted Publishing workflow is prepared. It requires repository
  environment and PyPI publisher configuration and is not run by this release.

## Install this exact release

```bash
uv tool install "git+https://github.com/huguryildiz/research-graph@v0.2.1"
rgraph demo --scenario 1
```

Or run it without a persistent install:

```bash
uvx --isolated \
  --from "git+https://github.com/huguryildiz/research-graph@v0.2.1" \
  rgraph demo --scenario 1
```

The demo is a synthetic fixture. Its passing gates establish the conditions
printed by those gates; they do not establish scientific correctness.

## Known issue

In the tagged v0.2.1 package, `rgraph trace` can report an `OPEN` protocol and
exit `1` for a real run that began from the normal open template even after a
current, valid H4 decision froze the protocol. This is a trace false-negative;
it does not make an invalid H4 pass. The H4 record, frozen artifact, and their
hash binding remain directly checkable. [Issue #4](https://github.com/huguryildiz/research-graph/issues/4)
tracks the limitation. Main commit `a07eca1` derives trace status from the valid
H4 decision; that correction will ship in the next patch release rather than
moving the published v0.2.1 tag.

## Compatibility

- Python 3.11, 3.12, and 3.13.
- Linux, macOS, and Windows are covered by the test matrix.
- Exit codes remain `0` for success, `1` for a gate/lint failure, and `2` for a
  usage, configuration, or provider-preflight failure.
- Recorded challenge decisions created before this release candidate do not
  contain executable invocation provenance and must be re-run. The synthetic
  example is explicitly exempt because it already states that no provider ran.
