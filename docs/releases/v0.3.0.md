# v0.3.0 — a loopback evidence desk, and terminal-only human decisions

`v0.3.0` adds a local browser interface for reading a run, and removes the one
path through which that interface could have recorded a decision on a person's
behalf. It does not add an agent scheduler, a continuous execution loop, or
model API orchestration.

The release was cut after a pre-publish audit, a second adversarial review of
that audit, and an independent verification pass over the fixes. What that
process found is recorded below, including what it found in the first draft of
this release.

## What changed

- **`rgraph ui`.** A browser interface presents the current workflow, gates,
  artifact health and claim-to-raw-data traces in the same midnight graph
  language as `architecture.html`. It binds only to loopback, refuses a
  non-loopback `--host`, rejects non-loopback `Host` headers, accepts mutations
  only with a per-session token compared with `secrets.compare_digest`, ships
  inside the wheel, and reuses the existing validated run loader. It adds no
  database, remote service or model API client.
- **The browser does not record human or final decisions.** It displays their
  state and prints the single terminal command that records each one. Work-unit,
  reviewer and revision actions keep their separate, single-use approval bound
  to the exact plan shown. See *What the audit changed* below.
- **Gate definitions carry a `criterion:` field**, exposed as
  `config.Gate.criterion` for terminal and browser views.
- **`scripts/generate_architecture_contracts.py`** regenerates the contract
  blocks inside the hand-maintained architecture plate; `--check` detects drift
  without writing. SVG geometry, CSS, theme, layout, prose and interaction code
  remain hand-maintained and are left byte-for-byte untouched.
- `rgraph trace` derives protocol-freeze status from the current, valid H4
  decision instead of the unchanged `meta.protocol` template flag. This closes
  the v0.2.1 trace false-negative recorded in that release's notes and in
  [Issue #4](https://github.com/huguryildiz/research-graph/issues/4).
- `rgraph ui` rejects ports outside `1..65535` as usage errors (exit `2`)
  without a traceback.
- `rgraph setup` warns before assigning the unverified model name `default` to a
  provider that has no known setup default.
- The package declares its direct `referencing` dependency. Wheel CI now starts
  `rgraph ui --no-open` outside the checkout and fetches its packaged JavaScript.

## What the audit changed

A pre-publish audit found that with `rgraph ui` running, any local process could
read the session token from an anonymous `GET /` and then `POST` a completed
human attestation or a final release decision — no terminal, no person. The CLI
refuses exactly this (`rgraph decide` will not take its answers from a pipe),
and the release candidate's own changelog claimed the UI added no scripted
approval path. That claim was false.

`/api/decide` and `/api/review` were removed rather than hardened. A verifier
whose own claim does not hold is worth less than no verifier, and no
session-token scheme makes an HTTP request into a person reading an artifact.
The three non-interactive execution endpoints (`next`, `challenge`, `revise`)
were deliberately kept: their CLI equivalents are also non-interactive, so
removing them would have been a change the finding did not justify.

The same audit corrected the landing page, which claimed four of the nine gates
"cannot be answered by a program". A pseudo-terminal disproves that, and the
README already said so. The landing page now carries the same qualification the
README does.

## The honesty limit, restated

A terminal is a workflow control. It cannot authenticate a person, and it cannot
distinguish one from software driving a pseudo-terminal. Human decisions are
attributable to a self-declared name, not to a verified identity. Nothing in
this release changes that, and no gate in this kit determines scientific
correctness.

## Install this exact release

```bash
uv tool install "git+https://github.com/huguryildiz/research-graph@v0.3.0"
rgraph demo --scenario 1
```

Or run it without a persistent install:

```bash
uvx --isolated \
  --from "git+https://github.com/huguryildiz/research-graph@v0.3.0" \
  rgraph demo --scenario 1
```

The demo is a synthetic fixture. Its passing gates establish the conditions
printed by those gates; they do not establish scientific correctness.

## Upgrading from v0.2.1

No run-directory migration is required; artifacts, gate records and execution
receipts are unchanged.

If you scripted anything against `POST /api/decide` or `POST /api/review`, those
endpoints now return `404`. Use `rgraph decide <GATE>` and `rgraph review` at a
terminal instead. That is the point of the change.

## Compatibility

- Python 3.11, 3.12, and 3.13.
- Linux, macOS, and Windows are covered by the test matrix.
- Exit codes remain `0` for success, `1` for a gate/lint failure, and `2` for a
  usage, configuration, or provider-preflight failure. A traceback is a bug.
- Not published on PyPI. Use the tag-pinned GitHub commands above.
