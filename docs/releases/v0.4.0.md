# v0.4.0 — the browser becomes the ordinary control surface

`v0.4.0` makes the local application the place a study is started, run and read,
and closes the gap between what the published pages described and what the
pinned install command actually delivered. It still adds no agent scheduler, no
continuous execution loop, and no model API client.

## What changed

- **`rgraph ui` in a directory with no study opens a launcher**, not an error:
  run the bundled demo, start a new study, reopen the one in this folder, pick a
  recent one, or open one by path.
- **A new-study wizard** — ten plain-language steps from question to a sealed run
  whose first checkpoint is `AWAITING` a human decision. It never asks for a
  provider identifier, a run path or a line of JSON, and writes nothing until the
  last step.
- **A study map replaces the stage columns.** One spine, in the order the graph
  produces it, derived from `graph.yaml` rather than listed in JavaScript. Return
  edges are drawn only where a revision was actually spent.
- **The reference architecture shows where the open study stands.**
  `architecture.html` is served by the application and marked with the study's
  position; the committed document and the published site keep no study behind
  them, because the live layer is injected into the response and never written to
  the file.
- **A background execution manager and console.** An approved plan runs as a
  child process of the local application, with an ordered event sequence, a
  bounded redacted transcript, and states derived only from what was observed. A
  server that restarts marks what it can no longer see `INTERRUPTED`.

The browser still cannot record a human decision. There is no `/api/decide` and
no `/api/review`, and a test fails if either appears.

## What this release fixes for people who followed the README

Two defects here were found by auditing the published artefacts rather than the
code, and both would have met a newcomer first.

- **A provider CLI installed under a Windows executable extension now starts.**
  npm writes the provider as `claude.cmd`, and a launch that deliberately never
  goes through a shell does not apply `PATHEXT` to a bare name. A provider that
  `doctor` reported as `FOUND` therefore failed to start on Windows — from the
  terminal and from the browser alike. Both launch paths now resolve `argv[0]`
  against the PATH the child is given.
- **The install commands now reach the release they describe.** README and the
  landing page pinned `v0.3.0` while describing the control room that arrived
  after it. A reader who followed them installed a build with no launcher, where
  `rgraph ui` in an ordinary directory answered `not a run directory`.

## Upgrading

```bash
uv tool install --force "git+https://github.com/huguryildiz/research-graph@v0.4.0"
```

Runs sealed by `v0.3.0` are read unchanged; no artifact, schema or gate record
format moved in this release.
