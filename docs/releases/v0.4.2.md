# v0.4.2 — hardened inputs, honest provider status, and browser reflow

`v0.4.2` closes the release-candidate gaps found after the local browser and
provider-onboarding audit. It changes no artifact schema, provenance rule, gate
condition, or terminal-only human-decision boundary.

## What changed

- Explicitly empty `--preset`, `--from`, and `--unit` values now exit `2`; setup
  and init do not write anything after these invalid inputs.
- `/api/next/preview` returns HTTP 400 for non-string or empty unit identifiers,
  and `rgraph ui --host ::1` now uses a real IPv6 socket with a bracketed URL.
- Qwen, Kimi, and DeepSeek remain configurable, but their
  documentation-derived command templates are visibly marked **DRAFT** in the
  terminal setup, preflight, local application, and public configurator. Users
  are told to verify CLI help and probe the selected model before use.
- An unanswered human decision appears as `[WAIT] Decision` under an overall
  `AWAITING` gate. This is a presentation correction; the gate still refuses to
  pass and exits `1` until a person answers at a terminal.
- Mobile layout now reflows when rem-based text is enlarged to 200%. A dedicated
  pinned-Chromium CI job checks desktop focus trapping, mobile overflow, touch
  targets, and enlarged text.

## Install this exact release

```bash
uv tool install rgraph==0.4.2
rgraph demo --scenario 1
```

Or run it without a persistent install:

```bash
uvx --isolated --from rgraph==0.4.2 rgraph demo --scenario 1
```

## Compatibility and limits

- Python 3.11, 3.12, and 3.13 remain supported.
- Existing run directories require no migration.
- Exit codes remain `0` for success, `1` for a gate or lint failure, and `2` for
  usage or configuration failure.
- The bundled run is synthetic. This release verifies the declared mechanical
  contracts; it does not establish scientific correctness or evidence a real
  end-to-end multi-agent study.
