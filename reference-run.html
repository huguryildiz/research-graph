Known limitations

Why this evidence is labeled historical and partial.

  1. The run started from commit f2b89cc and crossed successive v0.2.1 release-candidate wheels. It is not a clean run made exclusively with one final tagged package.
  2. u01–u05 predate host-issued execution receipts; retained provider logs do not supply the same attribution strength.
  3. Tagged v0.2.1 produced a trace false negative from an unchanged template flag. A later fix derives the frozen state from the valid H4 decision; no sealed run hash was hand-edited.
  4. M1 records SEPARATE MODEL, not SEPARATE PROVIDER, and retains that caveat.
  5. Several planning timestamps are rounded and do not independently establish ordering; the input-hash DAG records the ordering.
  6. The figure registry and figure-generation code are hash-bound, but rendered PNG, SVG, and PDF figures were not produced.
  7. Raw provider logs and receipts are withheld because they retain a named identity and absolute local paths. The facts above are a deliberately redacted public extract.

What this run does—and does not—show

It shows that real provider calls, versioned artifacts, provenance hashes, reviewer separation, gate conditions, and terminal-recorded human decisions completed one end-to-end graph. It does not establish scientific correctness, provider reliability, autonomous orchestration, or current-release quality. Because it crossed release-candidate builds, it is not a qualification run for the current release.
