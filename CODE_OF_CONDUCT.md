# Code of Conduct

## The short version

Argue with the claim, not the person making it. Disagreement about whether a gate
is right, whether a check proves what it says, or whether a finding is real is
the point of this repository — that is a technical argument, and it should read
like one.

## Expected

- Say what you verified and how. "This fails on my machine" is a start; the
  command, the exit code and the output is a report.
- Accept correction on the evidence. Being wrong about a mechanism is ordinary.
- Assume the other person read the docs and still found them unclear. If they
  did not, point at the section rather than at them.

## Not accepted

Harassment, personal attacks, demeaning comments, unwelcome attention, or
publishing anyone's private information. Sustained disruption of a discussion
after being asked to stop.

Passing off other people's work as your own, or fabricating evidence in an issue
or pull request, is also out of bounds here. A project about honest provenance
does not get to be relaxed about that.

## Enforcement

Report a problem to the maintainer through a
[private security advisory](https://github.com/huguryildiz/research-graph/security/advisories/new)
if it involves anything you would not put in a public issue, or by opening an
issue otherwise. Reports are handled by the maintainer, who may edit, hide, or
delete contributions and block accounts.

This is a small project with one maintainer. There is no committee and no appeal
process — decisions will be explained, and that is the extent of it.
